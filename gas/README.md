# ตั้งค่า GAS สำหรับชีตจริง

ไฟล์: `Code.gs` ใช้ชีตจริง ID ใหม่แล้ว เป็นโค้ดแทนของเดิมทั้งไฟล์ ไม่ใช่ให้นำไปต่อท้ายจนมี `doGet` ซ้ำ

## ก่อนเริ่ม

1. ทำสำเนาชีตจริงสำรองก่อน เพราะฟังก์ชันเตรียมข้อมูลจะเพิ่มคอลัมน์และตารางตรวจจับคู่
2. เปิด Apps Script ของชีตจริง วาง `Code.gs` แทนไฟล์เดิม แล้ว Save
3. ต้องมีแท็บชื่อ `รอบ 1` และ `รอบ 2` ตรงกัน หรือแก้ `CONFIG.rounds`
4. เลือกฟังก์ชันจาก dropdown บน editor แล้วกด Run ทีละฟังก์ชัน ไม่กด Run `doGet` (ใช้ URL สำหรับทดสอบ doGet)

## รันตามลำดับ

### 1. `run01_prepareSheets`

- อนุญาตสิทธิ์ Spreadsheet ตอน Google ถาม
- เพิ่ม `source_id`, `record_id`, `published`, `images_json`, `image_status` ท้ายแท็บทั้งสอง
- `source_id` เป็น ID ของแถวต้นทาง ห้ามแก้; `record_id` เป็น ID ของกิจการที่ใช้รวมรายการ
- สร้าง ID แบบ UUID ให้เฉพาะแถวมีชื่อ และตั้ง `published=FALSE` เฉพาะช่องว่าง ไม่ทับค่าเดิม
- รันซ้ำได้; ไม่มีการลบหรือแก้คอลัมน์ข้อมูลต้นฉบับ

### 2. `run02_createMatchReview`

สร้างแท็บ `ตรวจจับคู่` ให้ตรวจเอง โค้ดเสนอจากชื่อไทย/อังกฤษที่เท่ากันหลังปรับช่องว่างและตัวพิมพ์เท่านั้น ไม่เดาจากเบอร์และไม่อนุมัติคู่ใดอัตโนมัติ

ในแท็บตรวจจับคู่:

- ตรวจ `round2_name` ว่าตรงกับ `round1_name` จริงหรือไม่
- ถ้าชื่อสะกดต่างกันจนไม่พบคู่ ให้นำ `source_id` ของรอบ 1 ที่ถูกต้องมาใส่ `round1_source_id` เอง (ชื่อแสดงไว้ช่วยตรวจ ไม่ใช่ key จับคู่)
- ติ๊ก `approved` เฉพาะคู่ที่ถูกต้อง; ถ้ามีหลายข้อเสนอให้เลือกคู่เดียวต่อแถวรอบ 2
- กิจการมีเฉพาะรอบ 2 ปล่อย `approved=FALSE` และช่อง round1 ว่างได้ ไม่ต้องจับคู่เพื่อเพิ่มรายใหม่
- ฟังก์ชันไม่เขียนทับแท็บตรวจเดิม ถ้าจะสร้างใหม่ให้เปลี่ยนชื่อแท็บเดิมเก็บประวัติก่อน

### 3. `run03_applyApprovedMatches`

ทำให้ `record_id` ของรอบ 2 เท่ากับกิจการรอบ 1 เฉพาะคู่ที่อนุมัติ ไม่ย้ายแถว ไม่ลบแถว ไม่เปลี่ยน `source_id` และไม่เปลี่ยน `published` รันซ้ำได้

**ข้อมูลซ้ำภายในแท็บเดียวกัน:** ยังต้องตรวจด้วยคน ถ้ายืนยันว่าคือกิจการเดียว ให้ใช้ `record_id` เดียวกันทั้งรายการนั้น; ถ้ากิจการเดียวหลายหมวด endpoint จะรวมหมวดโดยไม่ทิ้งหมวดเดิม ข้อมูลค่าที่ขัดกันยังต้องจัดให้ถูกต้องในชีต (แถวที่อ่านภายหลังและมีค่าจะชนะ)

### 4. `run04_syncImagesBatch` — กดซ้ำจนเหลือ 0

- ตอนใช้ DriveApp ครั้งแรก อาจต้อง authorize สิทธิ์ Drive เพิ่ม
- อ่านครั้งละ 5 แถว บัญชีที่รันต้องอ่านโฟลเดอร์ใน `ลิ้งรูป` ได้
- อ่านเฉพาะรูปและเฉพาะไฟล์ที่ตรวจได้ว่าแชร์ Anyone/Anyone with link ไม่เปลี่ยนสิทธิ์ไฟล์ให้เอง
- เรียงตามชื่อไฟล์แล้ว ID และเก็บสูงสุด 12 รูปต่อแถว; รูปแรกจะเป็นตัวเลือกปกเริ่มต้นเมื่อเชื่อมเว็บ
- โค้ดอ่านเฉพาะโฟลเดอร์ตรงนั้น ไม่เดินเข้าโฟลเดอร์ย่อย และไม่อ่านช่องเอกสารทะเบียนนิติบุคคล
- ดู progress ใน Execution log และสถานะใน `image_status`

| สถานะ | ความหมาย |
| --- | --- |
| OK | พบรูปที่มีสิทธิ์สาธารณะตามที่ API รายงาน |
| NO_FOLDER | ช่องว่าง/เขียนรอบ 2/ไม่ใช่ลิงก์โฟลเดอร์ |
| NO_PUBLIC_IMAGES | ไม่พบไฟล์รูปที่ API รายงานว่าเป็นสาธารณะ |
| ERROR | อ่านไม่ได้ ให้ดู log และตรวจบัญชี/สิทธิ์ |

การแชร์โฟลเดอร์เฉพาะอีเมลผู้พัฒนาไม่ทำให้ผู้ชมเว็บโหลดรูปได้ ต้องทดสอบไฟล์จริงแบบไม่ login ด้วย; การตรวจ access เป็นเพียงขั้นต้นและไม่รับประกันว่ารูปโหลดได้ทุกกรณี

ถ้าแก้สิทธิ์หรือลิงก์ของรายการที่ผิดพลาด ให้รัน `run05_retryImageErrors` แล้วรัน `run04` ซ้ำ
ถ้ารายการเดิมเป็น OK แต่เปลี่ยนรูป/เพิ่มรูป ให้ล้าง `image_status` ของแถวนั้นเอง แล้วรัน `run04` ใหม่ การอ่านรูปเป็น batch นี้ **ไม่ซิงก์ Drive อัตโนมัติ** ต้องรันเมื่อรูปเปลี่ยนหรือเพิ่ม trigger ภายหลังตามที่ตกลง

### 5. อนุมัติการเผยแพร่ในชีต

- ตั้ง `published=TRUE` เฉพาะแถวที่ได้รับอนุญาตให้เผยแพร่; FALSE/ว่างไม่ส่งออก
- ถ้าต้องการใช้ข้อมูลของกิจการนั้นจากทั้งสองรอบ ต้องอนุมัติแถวของทั้งสองรอบ ข้อมูลแถวที่ไม่อนุมัติไม่ถูกนำมาเติม
- ไม่อนุมัติรายการที่ยินยอมเฉพาะวิจัยหรือยังไม่ยืนยันสิทธิ์โดยอัตโนมัติ
- การเพิ่มรูป/จับคู่ไม่ได้ทำให้ `published` เป็น TRUE

### 6. `run06_previewPublicData`

ตรวจจำนวนกิจการหลังรวม และจำนวนที่มีรูป โดยไม่พิมพ์รายชื่อ/เบอร์/อีเมลทั้งหมดลง log ถ้าไม่มีแถว TRUE จำนวนจะเป็น 0 ซึ่งถูกต้อง

### 7. Deploy และส่ง URL ใหม่

Deploy → Manage deployments → Edit → New version → Deploy (หรือ New deployment หากเป็นโปรเจกต์ใหม่) ตั้งให้รันด้วยบัญชีที่อ่านชีต/โฟลเดอร์ได้ ตรวจนโยบายการเข้าถึงกับผู้ว่าจ้าง

ทดสอบ `/exec?action=all` ผ่าน browser:

- รูปแบบยังเป็น `{ sheets: [{ name: "Directory", gid: 0, rows: [...] }] }`
- `action=all` ใหม่คือ **ทั้งหมดที่อนุมัติหลังรวม** ไม่ใช่ข้อมูลดิบทุกแท็บอีกต่อไป
- แต่ละรายการมี `record_id`, ชื่อ, หมวด, โทร, อีเมล, เว็บไซต์/ผลงาน และ `images` แบบ `{id, name, mimeType}`
- แถวรอบ 2 เติมข้อมูลที่มีค่า; ช่องว่างไม่ทับข้อมูลรอบ 1; กิจการใหม่รอบ 2 เพิ่มให้เมื่ออนุมัติ
- ไม่ส่งชื่อผู้เข้าร่วม จำนวนผู้เข้าร่วม ข้อจำกัดอาหารของผู้เข้าร่วม หมายเหตุ เอกสารทะเบียน หรือข้อมูลความยินยอมออก endpoint
- `categories` รองรับหลายหมวด; `display_category` รวมชื่อเพื่อ compatibility ชั่วคราว

**ส่ง URL `/exec?action=all` หลัง deploy กลับมา** แล้วจะปรับเว็บให้อ่าน schema ใหม่ (อีเมลที่แยกไว้, หลายหมวด, description และรูป file IDs) ขณะนี้เว็บยังเชื่อม endpoint เดโม่เดิม โค้ดนี้ไม่ได้เปลี่ยนเว็บเอง

## ข้อจำกัดที่ยังต้องตรวจด้วยคน

สคริปต์เตรียมคอลัมน์/อ่านรูป/รวมรายการได้ แต่ไม่ตัดสินใจแทนเรื่องกิจการที่ชื่อคล้ายกัน สิทธิ์เผยแพร่ และค่าข้อมูลที่ขัดกัน หากใช้ Drive ตรงกับเว็บจริงต้องพิจารณาโควตา/สิทธิ์และการให้บริการรูปผ่าน storage หรือ server ที่จำกัด file IDs

node gas/Code.test.cjs
